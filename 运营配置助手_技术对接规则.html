与技术对齐规则

版本：2026-09-08　整理：运营（美惠）　用途：对接会书面口径，不是再画一套页面

一句话 这是盖在原后台之上的运营工作台。不新建商品库、不改原 ID、不改原权限。演示页面形状已定，下面只写上线前必须和技术对齐的规则。干活在技术；字段是否仍在用听张旭；入口和任务形态听运营。

1. 系统定位（先对齐这个，再谈接口）

正式链路：新版管理页面 → 原后台接口 → 原数据库 → App / 小程序 / PC。

  • 不是外挂另一套业务数据。
  • 不是把项目管理做成「全部商品清单」。项目管理 = 项目 → 专业 → 子级；清单和批量任务是另外两件事。
  • Hash 路由便于接入现有后台。登录、菜单权限、按钮权限沿用原体系。
  • 名称只用于展示；读写一律用后台返回的真实 ID。

2. 谁拍板什么

角色拍板范围
运营（美惠）工作台入口位置、左侧名称、批量任务怎么操作（一屏填规则、按科室勾专业、一次生成）。
张旭 / 现网后台哪些字段还在用、枚举和售价、试听内容从哪来。已停用的模块不要按旧图恢复。
技术接口、拆请求、服务端校验、权限、搜索、撤回落库、分页、上传。

已确认例子：旧「App免费体验课」里的配置内容 / 关联小节长期不用。现网是商品页「配置头图免费试听 / 配置列表免费试听」。入口放在「App引流课管理」，名称按运营；字段按张旭。

3. 全局写入规则（优惠券、上下架、调价必须同一套）

3.1 一次保存 = 一批任务

运营在工作台点一次「保存」，语义是：同一规则，落到所有有效的「商品 × 专业」组合。后台如果只能逐条写，由适配层拆成 N 次请求，对运营仍是一次任务。

  • 覆盖不到的专业：跳过，不生成脏数据，并在结果里标明跳过原因。
  • 不要做成「每个专业再走一遍向导」。

3.2 15 秒内撤回 = 整批作废

运营已确认：

  • 保存成功后 15 秒内允许撤回。
  • 撤回必须是 整批：已写出的「商品 × 专业」全部收回，禁止留下一半有券、一半没有。
  • 撤回之后这次任务作废，运营 重新选范围再保存，不在半成品上续写。
  • 超过 15 秒：不能再靠这个撤回。之后只能走后台正常的下架、删除或再配一批，规则以后台为准。

写入中途失败（超时、部分接口失败、权限不足）：同样按 整批作废 处理，给运营明确失败原因，不要静默留下部分成功。撤回能力必须由服务端提供（操作单号 / 短时快照 / 可逆事务），不能只靠浏览器提示。

3.3 幂等

同一任务短时间重复点击保存，不能发两批真实优惠券或调价。请给出任务号或幂等键约定。

4. 价格与亏本（以后台为准）

  • 前端测算成交价只是预览，文案为「仅供参考」。
  • 成交价 大于 0 或等于 0 都可以保存；低于 0 才拦截亏本。
  • 满减门槛可以为 0（满 0 减 N 作为无门槛满减，允许配置）。
  • 商品当前无售价：前端不能编价格（尤其是中级职称精英班等）。只能提示无法确认是否低于 0。
  • 最终能否保存：必须用后台当时真实售价再算一遍。前端通过、后台不通过，以后台为准。

5. 按模块：需要技术对齐的事项

5.1 工程接入（全部已迁页面通用）

事项要求
替换演示数据去掉 localStorage / sessionStorage 当真源。列表、详情、写操作走原接口。
ID项目、专业、子级、商品、广告、页面一律用后台 ID。演示 ID 不得写入生产。
权限按钮接原权限指令。演示里固定操作人「美惠」不能当生产身份。
校验必填、状态、冲突、有效期、图片，服务端再校验一次。
操作人返回最后修改人、修改时间，便于追责。
枚举广告形式、投放位置、打开环境等 code 以后台字典为准，前端不发明新枚举。

5.2 项目管理

  • 上架列表与已下架列表分开，不要混在一张默认长表。
  • 所属项目为空的脏专业：放在「信息待补充」，不要猜填项目 ID。
  • 子级排序连续；无真实子级 ID 的不要编。
  • 删除 / 下架的服务端影响面（关联商品、广告）需技术说明，工作台只做确认，不假装无影响。

5.3 广告素材管理

  • 去向选商品：正式必须从商品库搜索（名称或商品 ID），选中后保存真实商品 ID。 原型手填作废。
  • 图片走现有上传，存后台返回的地址，不存浏览器本地图。
  • 像素、横竖、大小以后台上传接口为准。演示只拦明显方向错误。
  • 列表需服务端分页和组合筛选（原轮播约数百条，禁止一次拉全量当真）。
  • 复制 1 / 5 / 10 条：新 ID 由后台生成，默认进入今日下架；15 秒整批撤回。
  • 新记录默认下架，上架前走原冲突校验（同页轮播位、投放时间等）。

5.4 金刚区管理（含磁片区，同一模块）

  • 每个入口必须配置完整点击去向后才能启用。
  • 需要落到商品时，同样走商品搜索 ID，不手填。
  • 「光荣榜」业务含义已确认：App 刷题排行榜。正式 route code 由接口返回，前端不编路由名。
  • 项目 / 专业树接入后与项目管理同一数据源。
  • 15 秒整批撤回与广告同一策略。

5.5 AI 工具集管理

  • App 中部 6 个智能体入口，不擅自增删入口数量，除非现网已变。
  • 「推荐管理」现网未关联商品，不要在接入时编一批推荐商品。
  • 图标、推荐提问、营销周期：读写原配置；图标上传走现有资源服务。

5.6 意见反馈管理

  • 工作台先按「未处理 / 已处理」粗分，列表仍保留待处理、处理中、已回复、已关闭四档，落库用原状态。
  • 不要假设有启用 / 停用反馈入口的能力，除非现网本来就有。

5.7 App 优惠券管理

  • 列表是「任务」维度（一次配置生成多张「商品 × 专业」券），不要做成必须点进每一张券才能改。
  • 一次保存拆成 N 条写请求；失败或 15 秒撤回 = 整批作废，重新来。
  • 亏本拦截见第 4 节。无售价不编价。
  • 生效时间、截止时间必填；截止不能早于生效。

5.8 商品课程上下架 / 商品批量调价

  • 同一班型、一批专业、同一规则，一屏完成，不要四步向导。
  • 上下架：生效时间 + 截止时间都必填。上架 = 生效起可售、截止后停售。下架 = 生效起停售、截止结束本次下架窗口；是否自动恢复上架以后台为准。
  • 调价：只要生效时间。
  • 调价亏本、权限、15 秒整批撤回：与优惠券同一套写入策略。
  • 从「全部项目清单 / 临床商品清单」带入已选范围，接入后用明确的任务草稿或查询参数，不要依赖浏览器 sessionStorage。

5.9 App 引流课管理

  • 对应商品编辑里仍在用的「配置头图免费试听」「配置列表免费试听」。
  • 先选项目 + 专业，头图一条，列表可多条。
  • 第一个下拉：该专业下已有商品，走商品接口。
  • 第二个下拉：试听内容，选项必须等后台返回。禁止编造小节 ID。
  • 旧体验课「配置内容 / 关联小节 / 精华体验课」不要接入。

5.10 商品清单（全部项目清单 / 临床商品清单）

  • 这是挑货入口，不是项目管理。
  • 商品名称、售价、上下架状态、覆盖专业必须来自现网。
  • 中级职称等无价商品保持无价，直到后台有价。

6. 本期不要做、也不要编数据的页面

左侧入口口径
活动列表只标明入口。接入时用原活动接口和 ID，不在演示里编活动。
活动分类管理沿用原分类接口和 ID，不另建一套分类。
App 商品推荐管理接入后按原推荐规则读写，不编推荐商品。

这三页在现网字段未经张旭确认前，保持占位。不要为了「看起来齐」做假 CRUD。

7. 建议技术会先确认的清单（可当作会议议程）

  1. 批量写：任务单号、拆条方式、部分失败是否一律整批回滚（运营要求：是）。
  2. 15 秒撤回：服务端如何实现、过期后如何拒绝、与广告现网是否已有同类能力。
  3. 幂等键：重复保存如何去重。
  4. 售价接口：何时返回 null、亏本由哪个服务判定。
  5. 商品搜索接口：广告、金刚区、引流课共用还是各用各的。
  6. 引流课试听内容接口：字段名、与商品页现网是否同一套。
  7. 图片上传与像素校验现网规则原文。
  8. 光荣榜 / 刷题排行榜的 route code。
  9. 优惠券、调价、上下架的按钮权限点。
  10. 活动、推荐：现网是否仍用、接口是否还在；未确认则继续空着。

8. 验收时什么叫合格

  • 运营一次保存，后台出现的是完整一批，或完整没有；没有「成功 20 个专业、失败 19 个还挂着」。
  • 15 秒内撤回后，App 侧看不到这批券 / 这批价。
  • 无售价商品不会被前端写死一个编出来的价格。
  • 广告去向能搜到真实商品 ID。
  • 引流课第二个下拉要么有真数据，要么仍空，没有假小节。
  • 原后台 ID、权限、App 展示结果与改版前一致，只是运营操作路径变短。
