# 医考巴巴后台逻辑映射

> 目标：以现有后台为数据与接口事实来源，在不改变现有 ID、字段语义和关联关系的前提下，将“运营配置助手”作为外挂式前端，提高批量配置效率。

## 核心约束

- 现有后台的项目 ID、专业 ID、班型/商品 ID 是稳定身份键；展示名称不能代替 ID。
- 新界面允许重组信息架构和操作流程，但不能自行重编号、合并或推断旧对象。
- 所有写操作最终仍需映射到现有后台接口和权限体系。
- 开发初期只做数据读取、筛选、预览和模拟；真实提交需在接口、权限、校验及回滚机制确认后接入。
- 同名对象可能对应不同 ID，必须保留并显示必要的消歧信息。

```text

└── 专业 profession
    └── 子级 profession child
        └── 课程 / 班型 / 商品（具体关系待后续截图确认）
```

## 项目管理页面

### 搜索与操作

- 搜索条件：项目名称、状态。
- 页面动作：查询、新增。
- 行级动作：删除、编辑、上架/下架。
- 当前未见：多选、批量上下架、批量编辑、影响范围预览。

### 项目编辑表单（已确认）

- 项目名称：必填文本。
- 排序：必填数值。
- 状态：必填单选，上架 / 下架。
- 项目 ID 在编辑弹窗中不展示且不可修改。
- 操作：取消、确定。

### 项目上下架确认（已确认）

- 当前提示文案仅为“确定上架此项目吗？”（下架预计为对应文案，待实图确认）。
- 弹窗不展示项目名称、项目 ID、当前状态、目标状态、关联专业数量或可能的级联影响。
- 这是高风险的弱确认：长表中误点后，用户无法在弹窗内再次辨认对象。

## 专业管理页面

### 数据规模与字段

- 2026-08-28 截图基线中共观察到 `157` 条专业记录。
- 演示页已录入完整 `157` 条：上架 `117` 条、历史下架 `40` 条；日常列表默认只展示上架数据，历史下架数据不混入工作区。
- 字段：序号、专业 ID、专业名称、所属项目、状态、操作。
- 行级操作：子级管理、删除、编辑、上架/下架。

### 搜索与页面操作（已确认）

- 搜索条件：专业名称、所属项目、状态。
- 搜索操作：查询、重置。
- 创建与导入：新增、批量上传、下载模板。
- 当前未见：年份、创建/更新时间、最后使用时间、关联数量、历史/废弃标识、多选批量处理。

### 专业批量上传（已确认）

- 必须先选择“所属项目”。
- 上传文件入口文案为“批量上传专业”。
- 仅接受 `.xls` 和 `.xlsx` 格式。
- 必须为本批数据统一选择状态：下架 / 上架。
- 当前弹窗未展示文件名、待导入条数、字段校验、重复 ID/名称、冲突策略、错误行预览及导入结果。
- 由此可知：当前批量上传是“单项目 + 单状态 + Excel 专业数据”模型，不是跨项目的全局导入。

### 专业编辑表单（已确认）

- 专业名称：必填文本。
- 所属项目：必填单选下拉。
- 拼音：必填文本；示例 `yjcjzc`，具体生成与唯一性规则待确认。
- 排序：必填数值。
- 状态：必填单选，上架 / 下架。
- 专业 ID 在编辑弹窗中不展示且不可修改。
- 操作：取消、确定。

### 专业数据的实际语义

当前“专业”列表不是干净的专业学科表，而是历史运营对象集合，其中混合了：

- 真实专业/学科，如病理科、影像、药学。
- 考试类型，如考研、期末考试、规培结业考核。
- 职称/资格层级，如初级职称、中级职称、主管护师。
- 学历及学期阶段，如大二、大三、大四、专科期末。
- 地区性招考项目，如河北/安徽/河南/山东/四川专升本。
- 似产品或内容容器的对象，如本科题库。

因此外挂层不应直接将原字段“专业”当作业务分类；应保留原实体，另建可管理的展示分类与标签。

### 专业数据异常（截图观察）

- 上架、下架和长期废弃数据混排，仅有二值状态，无法表达“暂停”“归档”“废弃”或“异常”。
- 页面缺少年份、最后使用时间及关联内容数，不能安全判断历史数据是否可废弃。
- 已观察到同名不同 ID、近似名称不同 ID，以及所属项目为空的记录。
- 已观察到名称或所属项目空白的行，应在外挂中列入“数据异常”而非默认隐藏。

## 已确认的数据风险

### 同名不同 ID

- 公共预防：`330`、`631`
- 中西药：`364`、`285`
- 医学技术：`372`、`257`

因此，新 Demo 中所有选择、缓存、批量任务、日志和接口参数必须以 ID 为键。名称仅用于展示；同名时应追加 ID、状态、所属关系或其他业务信息帮助运营辨认。

### 状态与名称不是身份

- 同名项目可能同时存在不同上下架状态。

### 2026-08-28 技术确认后的展示口径

- “公共预防”项目已经停用，后续统一使用“公卫预防”（项目 ID `313`），不再新增“公共预防”。
- 日常管理只查看和维护上架数据，历史下架数据不需要补录到运营配置助手。
- “已停用数据”暂时只保留空白框架；以后新发生并确认需要下架的数据，再在该框架中登记。

### 原型交互验收口径（2026-08-28）

- 页面标题统一使用“信息待补充”，不再使用含义模糊的“数据异常”或“待核验”。
- 项目或专业在本工具中执行下架后，从上架工作列表移入“已下架”，保留原 ID，并显示灰色“已下架”标识。
- “已下架”支持编辑、重新上架和删除；左侧及移动端入口同步显示数量。
- 子级下架后保留在子级管理中，可通过“全部 / 上架 / 已下架”查看；已下架子级整行置灰并可重新上架。
- 子级排序采用上移/下移和自动连续编号，避免重复排序值。
- 删除项目、专业或子级后显示可操作的“撤回”提示；演示状态下可在提示有效期内恢复。
- “已下架”提供按名称或 ID 搜索、搜索图标、回车查询和重置功能。
- 排序值重复且不连续，不能据此推断业务层级。
- “序号”只反映当前列表位置，不能持久化引用。

## 外挂式前端的初步映射原则

```text
展示层：业务分组、搜索、批量选择、影响预览、AI 解释
规则层：项目/专业/班型/商品关联、适用范围、冲突与异常校验
适配层：把新界面的批量意图拆解为现有后台接口可接受的请求
事实层：沿用公司后台的 ID、状态、权限、数据与操作结果
```

- UI 可以把项目按业务意义重新分组，但提交参数必须使用原始项目 ID。
- 批量操作前应显示“对象名称 + ID + 当前状态 + 将变更为”。
- 出现同名对象时不得自动合并。
- 项目下架前需进一步确认是否存在专业、班型、商品或权益级联影响。
- 删除不应成为外挂的默认批量能力，除非技术侧明确接口语义、权限和恢复方式。
